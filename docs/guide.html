    Wielodostępność i white labelMulti-tenancy and white label

    Wszyscy brokerzy dzielą jedną bazę i jeden proces; każda tabela biznesowa ma kolumnę tenant_id. Broker jest rozpoznawany przy każdym żądaniu, w tej kolejności: subdomena *.localhost, parametr ?tenant=, nagłówek X-Tenant-Id (wysyłany przez SPA, bo proxy dev zmienia nagłówek Host), a na końcu broker domyślny. Jawnie podany, nieznany broker to błąd 400, a nie ciche przełączenie na domyślnego.

    All brokers share one database and one process; every business table has a tenant_id column. The broker is resolved on every request, in this order: *.localhost subdomain, ?tenant= parameter, X-Tenant-Id header (sent by the SPAs because the dev proxy rewrites the Host header) and finally the default broker. An explicitly requested but unknown broker is a 400, not a silent fallback.

    Angular 21: standalone i zonelessAngular 21: standalone and zoneless

    Projekt powstał poleceniem ng new --zoneless --test-runner=vitest. Nie ma NgModule: każdy komponent jest samodzielny (standalone to domyślne ustawienie od v19) i sam deklaruje swoje imports. Nie ma też zone.js: Angular nie „łata” już setTimeout, fetch i zdarzeń, tylko odświeża widok, gdy zmieni się sygnał czytany w szablonie, przyjdzie zdarzenie z szablonu albo zadziała async pipe. Mniej magii, mniejszy bundle, czytelne stosy wywołań.

    Cała konfiguracja aplikacji to lista providerów:

    The project was created with ng new --zoneless --test-runner=vitest. There are no NgModules: every component is standalone (the default since v19) and declares its own imports. There is no zone.js either: Angular no longer patches setTimeout, fetch and events; it re-renders when a signal read by a template changes, a template event fires or the async pipe emits. Less magic, smaller bundle, readable stack traces.

    Sygnały: signal, computed, effect, linkedSignalSignals: signal, computed, effect, linkedSignal

    Sygnał to wartość, która wie, kto ją czyta. signal() przechowuje stan, computed() wylicza stan pochodny leniwie i z pamięcią podręczną, effect() uruchamia efekt uboczny, gdy zmienią się czytane sygnały, a linkedSignal() to zapisywalny sygnał, który „resetuje się”, gdy zmieni się jego źródło. W zoneless Angularze sygnały są silnikiem odświeżania widoku.

    Serwis brokera eksponuje stan wyłącznie jako sygnały tylko do odczytu:

    A signal is a value that knows who reads it. signal() holds state, computed() derives state lazily and memoised, effect() runs a side effect when the signals it read change, and linkedSignal() is a writable signal that resets when its source changes. In zoneless Angular signals are the rendering engine.

  source: () => this.history.value(),
  computation: (points) => (points ?? []).map((p) => ({ t: Date.parse(p.t), price: p.price })),
});

constructor() {
  effect(() => {
    const live = this.stream.quotes().get(this.symbol());
    if (!live) return;
    const t = Date.parse(live.timestamp);
    untracked(() =>
      this.chart.update((points) =>
        points.length && points[points.length - 1].t >= t ? points : [...points.slice(-179), { t, price: live.mid }],
      ),
    );
  });
}

    httpResource: żądania HTTP jako sygnałyhttpResource: HTTP requests as signals

    httpResource zamienia GET w zasób reaktywny. Funkcja przekazana jako argument jest śledzona: jeśli czyta sygnał, zmiana tego sygnału automatycznie wysyła nowe żądanie (i anuluje poprzednie). Zasób wystawia value(), isLoading(), error(), hasValue() oraz metody reload() i set(). Działa przez HttpClient, więc przechodzi przez wszystkie interceptory.

    httpResource turns a GET into a reactive resource. The function you pass is tracked: if it reads a signal, changing that signal automatically sends a new request (cancelling the previous one). The resource exposes value(), isLoading(), error(), hasValue() plus reload() and set(). It uses HttpClient, so every interceptor applies.

    Funkcyjne interceptory HTTPFunctional HTTP interceptors

    Interceptor to zwykła funkcja (req, next) => Observable. Wewnątrz działa inject(), więc nie potrzeba klas ani tokenów HTTP_INTERCEPTORS. Mamy trzy, każdy z jedną odpowiedzialnością:

    An interceptor is a plain function (req, next) => Observable. inject() works inside it, so no classes or HTTP_INTERCEPTORS tokens are needed. We have three, each with one job:

    angular-client/src/app/core/interceptors.ts

    /** Adds X-Tenant-Id so the backend serves the right broker even though the dev proxy rewrites Host. */
export const tenantInterceptor: HttpInterceptorFn = (req, next) => {
  const id = inject(TenantService).requestedId();
  return next(id ? req.clone({ setHeaders: { 'X-Tenant-Id': id } }) : req);
};

/** Attaches the bearer token; a 401 on a protected call means the token is gone or expired. */
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const auth = inject(AuthService);
  const router = inject(Router);
  const token = auth.token();
  const authReq = token && !req.url.startsWith('/api/auth/') ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } }) : req;
  return next(authReq).pipe(
    catchError((error: unknown) => {
      if (error instanceof HttpErrorResponse && error.status === 401 && !req.url.startsWith('/api/auth/')) {
        auth.logout();
        void router.navigate(['/login'], { queryParams: { reason: 'expired' } });
      }
      return throwError(() => error);
    }),
  );
};

export const problemInterceptor: HttpInterceptorFn = (req, next) => {
  const toasts = inject(ToastService);
  return next(req).pipe(
    retry({
      count: req.method === 'GET' ? 2 : 0,
      delay: (error: unknown, attempt) =>
        error instanceof HttpErrorResponse && error.status === 503 ? timer(250 * attempt) : throwError(() => error),
    }),
    catchError((error: unknown) => {
      if (error instanceof HttpErrorResponse && (error.status === 0 || error.status >= 500)) {
        const problem = toProblem(error);
        toasts.show('error', problem.title ?? 'Error', `${problem.detail ?? ''} [${problemSlug(problem)}]`);
      }
      return throwError(() => error);
    }),
  );
};

    react-client/src/core/externalStore.ts

    export function createStore<T>(initial: T): Store<T> {
  let state = initial
  const listeners = new Set<() => void>()
  return {
    get: () => state,
    set(next) {
      const value = typeof next === 'function' ? (next as (prev: T) => T)(state) : next
      if (Object.is(value, state)) return
      state = value
      listeners.forEach((l) => l())
    },
    subscribe(listener) {
      listeners.add(listener)
      return () => listeners.delete(listener)
    },
  }
}

void on(OrderFilled fill) {

            () -> new IllegalStateException("No account for " + fill.userId()));
    BigDecimal cashDelta = FxRates.convert(fill.notional(), fill.currency(), account.currency())

    BigDecimal newQty = current.quantity().add(signedQty);

            case BUY -> current.quantity().multiply(current.avgPrice()).add(fill.notional())
                    .divide(newQty, MathContext.DECIMAL64);
            // sells realise P&L and keep the average cost of the remaining shares
            case SELL -> current.avgPrice();
        };
        repository.upsertPosition(account.id(), fill.symbol(), newQty, avg);

    SseEmitter subscribe(Tenant tenant) {
    var emitter = new SseEmitter(TIMEOUT.toMillis());
    var list = subscribers.computeIfAbsent(tenant.id(), id -> new CopyOnWriteArrayList<>());
    list.add(emitter);

    Zlecenia rynkowe i z limitemMarket and limit orders

    Zlecenie rynkowe realizuje się natychmiast po cenie ask (kupno) lub bid (sprzedaż) danego brokera. Zlecenie z limitem czeka jako OPEN, aż LimitOrderMatcher zobaczy cenę przecinającą limit; wtedy realizuje się po bieżącej, lepszej cenie. Przed każdą realizacją ponownie sprawdzamy środki i pozycje, a zmiany statusu to compare-and-set w SQL, więc anulowanie i realizacja nigdy nie wygrają obie.

    A market order fills immediately at the broker's ask (buy) or bid (sell). A limit order waits as OPEN until LimitOrderMatcher sees a price crossing the limit; it then fills at the current, better price. Funds and positions are re-checked before every fill, and status changes are a SQL compare-and-set, so a cancel and a fill can never both win.

public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
        throws InterruptedException {
    var s = simulator.settings();
    long delay = s.latencyMs() + (s.jitterMs() > 0 ? ThreadLocalRandom.current().nextInt(s.jitterMs() + 1) : 0);

    OAuth2 resource server i JWT RS256OAuth2 resource server and RS256 JWT

    API jest bezstanowym serwerem zasobów OAuth2: nie ma sesji ani ciasteczek, każde chronione wywołanie niesie Authorization: Bearer <JWT>. Token jest podpisany algorytmem RS256 (RSA + SHA-256): klucz prywatny podpisuje, a każdy, kto zna klucz publiczny (z JWKS), może sprawdzić podpis. To asymetria pozwala oddzielić wydawcę tokenów od API.

    W trybie dev backend sam jest małym dostawcą tożsamości: przy starcie generuje parę kluczy RSA 2048, sprawdza hasło (BCrypt) w tabeli app_user i wydaje token przez NimbusJwtEncoder. Publikuje też dokument odkrywania OIDC i JWKS.

    The API is a stateless OAuth2 resource server: no session, no cookies; every protected call carries Authorization: Bearer <JWT>. The token is signed with RS256 (RSA + SHA-256): the private key signs and anyone with the public key (from the JWKS) can verify. This asymmetry is what lets us separate the token issuer from the API.

    In dev mode the backend itself is a tiny identity provider: at startup it generates an RSA 2048 key pair, checks the password (BCrypt) in the app_user table and issues the token through NimbusJwtEncoder. It also publishes an OIDC discovery document and a JWKS.

    Warstwy obrony

    • Uwierzytelnienie: podpis, iss i exp sprawdzane przy każdym żądaniu (401 jako Problem Details).
    • Autoryzacja ról: roles → ROLE_TRADER/ROLE_VIEWER; tylko TRADER składa i anuluje zlecenia (403).
    • Izolacja brokerów: TenantMatchFilter odrzuca token innego brokera (403 tenant-mismatch).
    • Reguły biznesowe: flagi brokera (handel, limity) i klasy aktywów sprawdza serwis, nie UI.
    • Stały czas odpowiedzi logowania: dla nieznanego użytkownika porównujemy hasło z atrapą hasha, żeby czas nie zdradzał, czy konto istnieje.
    • Brak tokenu w URL: SSE z cenami jest publiczne, więc token nigdy nie trafia do adresu ani logów proxy.

    Layers of defence

    • Authentication: signature, iss and exp checked on every request (401 as Problem Details).
    • Role authorization: roles → ROLE_TRADER/ROLE_VIEWER; only TRADER places and cancels orders (403).
    • Broker isolation: TenantMatchFilter rejects another broker's token (403 tenant-mismatch).
    • Business rules: broker flags (trading, limits) and asset classes are enforced by the service, not the UI.
    • Constant-time login: for an unknown user we still compare against a dummy hash so timing does not reveal whether an account exists.
    • No token in URLs: the price SSE is public, so a token never ends up in an address or proxy logs.
    Przechowywanie tokenu w SPA. Klienci trzymają token w pamięci i sessionStorage (znika po zamknięciu karty). To kompromis szkoleniowy; w produkcji rozważ wzorzec BFF (token po stronie serwera, ciasteczko HttpOnly) i ścisłe CSP.Token storage in SPAs. The clients keep the token in memory and sessionStorage (gone when the tab closes). It is a training compromise; in production consider the BFF pattern (token on the server, HttpOnly cookie) and a strict CSP.

    Zlecenia STOP, STOP LIMIT oraz Stop Loss / Take ProfitSTOP and STOP LIMIT orders, Stop Loss / Take Profit

    Dojrzałe platformy oferują więcej niż „kup teraz” i „kup po cenie X”. Doszły dwa typy zleceń oczekujących i ochrona pozycji:

    • STOP: „kup, gdy cena wzrośnie do X” (wybicie) albo „sprzedaj, gdy spadnie do X”. Po osiągnięciu stopu staje się zleceniem rynkowym.
    • STOP LIMIT: jak STOP, ale po wyzwoleniu staje się zleceniem z limitem (kolumna triggered), więc nie wykona się gorzej niż limit.
    • SL/TP przy zakupie: po realizacji portfel zapisuje je na pozycji, a ProtectionMonitor zamyka całą pozycję zleceniem SELL z origin = STOP_LOSS lub TAKE_PROFIT. SL/TP można też edytować na otwartej pozycji (PUT /api/portfolio/positions/{symbol}/protection).

    Mature platforms offer more than "buy now" and "buy at X". Two pending order types and position protection were added:

    • STOP: "buy when the price rises to X" (breakout) or "sell when it falls to X". Once the stop is reached it becomes a market order.
    • STOP LIMIT: like STOP, but once triggered it becomes a limit order (the triggered column), so it never fills worse than the limit.
    • SL/TP on a buy: when it fills the portfolio stores them on the position, and ProtectionMonitor closes the whole position with a SELL whose origin is STOP_LOSS or TAKE_PROFIT. SL/TP can also be edited on an open position (PUT /api/portfolio/positions/{symbol}/protection).

    static List<Candle> candles(List<PriceEngine.PricePoint> points, Duration interval, int limit) {
    long size = interval.toMillis();
    List<Candle> result = new ArrayList<>();
    long bucket = Long.MIN_VALUE;
    BigDecimal open = null, high = null, low = null, close = null;
    int ticks = 0;
    for (var p : points) {
        long b = Math.floorDiv(p.at().toEpochMilli(), size) * size;
        if (b != bucket) {
            if (open != null) {
                result.add(new Candle(Instant.ofEpochMilli(bucket), open, high, low, close, ticks));
            }
            bucket = b;
            open = high = low = close = p.price();
            ticks = 0;
        }
        high = high.max(p.price());
        low = low.min(p.price());
        close = p.price();
        ticks++;
    }

    export function rsi(values: readonly number[], period = 14): (number | null)[] {
  const out: (number | null)[] = values.map(() => null);
  if (values.length <= period) return out;
  let gain = 0;
  let loss = 0;
  for (let i = 1; i <= period; i++) {
    const change = values[i] - values[i - 1];
    if (change >= 0) gain += change;
    else loss -= change;
  }
  gain /= period;
  loss /= period;
  out[period] = loss === 0 ? 100 : 100 - 100 / (1 + gain / loss);
  for (let i = period + 1; i < values.length; i++) {
    const change = values[i] - values[i - 1];
    gain = (gain * (period - 1) + Math.max(change, 0)) / period;
    loss = (loss * (period - 1) + Math.max(-change, 0)) / period;
    out[i] = loss === 0 ? 100 : 100 - 100 / (1 + gain / loss);
  }
  return out;
}
